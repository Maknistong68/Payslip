# WhatsApp-based delivery of ~1,000 individual PDF payslips without the Business API (Saudi/GCC focus)

Scope note: Everything below treats "solution" as free, no-API, no-server, no-BSP. Paid WhatsApp Business Platform figures appear only as contrast. State of play is as of October 2026; dates of policy/feature changes are flagged where sources give them. Several official faq.whatsapp.com pages could not be fetched in full (the site returned "Sorry, something went wrong" to direct fetches), so some official quotes come from search-engine snippets of those pages and are marked as such.

## Key Question 1: Can a wa.me / whatsapp:// link pre-attach a file? What exactly can it prefill, and what is the URL/phone format for Saudi (+966) numbers?

### Takeaway
No. Click-to-chat can prefill only (a) the recipient's phone number and (b) a URL-encoded text message; there is no parameter for attachments of any kind. For Saudi mobiles the link is `https://wa.me/9665XXXXXXXX` (country code 966 + 9 digits, leading 0 dropped, no "+").

### Cited Findings
- Official click-to-chat format: "Use https://wa.me/<number> where the <number> is a full phone number in international format"; WhatsApp says to omit "any zeroes, brackets, or dashes"; the FAQ's own example of a valid link is `https://wa.me/1XXXXXXXXXX` and its invalid example is `https://wa.me/+001-(XXX)XXXXXXX` — [WhatsApp Help Center: How to use click to chat](https://faq.whatsapp.com/5913398998672934/)
- Pre-filled text: "Use https://wa.me/whatsappphonenumber?text=urlencodedtext where whatsappphonenumber is a full phone number in international format and urlencodedtext is the URL-encoded pre-filled message" — [WhatsApp Help Center: How to use click to chat](https://faq.whatsapp.com/5913398998672934/)
- A recipient-less variant `https://wa.me/?text=...` opens WhatsApp with the text and lets the sender choose the contact; `https://api.whatsapp.com/send?phone=<number>` is the equivalent long form — [Linkly guide (third-party, attributes to WhatsApp Help Center)](https://linklyhq.com/blog/whatsapp-link-generator)
- The only documented parameters are phone and text; a click-to-chat link "can only create a link to a phone number with some text via it, not to attach a file automatically" (Adobe Community answer citing WhatsApp documentation, in a thread about adding a "send PDF on WhatsApp" button to an Acrobat form) — [Adobe Community](https://community.adobe.com/t5/acrobat-discussions/send-pdf-file-on-whatsapp/m-p/13905667)
- The desktop deep link `whatsapp://send?phone=XXXXXXXXXXXXX&text=Hello` opens the installed Windows WhatsApp app with the chat pre-composed (community report, not official docs) — [Edureka community](https://www.edureka.co/community/173303/open-whatsapp-windows-directly-from-python-program-using-url); a Russian developer forum describes the `whatsapp://send/?phone=` scheme as undocumented, noting WhatsApp's own examples route via whatsapp.com — [qna.habr.com](https://qna.habr.com/q/370447)
- On desktop, an `api.whatsapp.com` link "opens the WhatsApp application if it's installed or WhatsApp Web otherwise" (WordPress plugin developer) — [WordPress.org support](https://wordpress.org/support/?p=10680850)
- WhatsApp's general international-format page says a number in international format starts with "+" then country code then local number, and warns against leading zeros — [WhatsApp Help Center: About international phone number format](https://faq.whatsapp.com/1294841057948784) (note the wa.me page explicitly omits the "+")
- Saudi numbering: domestic mobile numbers are 10 digits starting 05; internationally the country code is +966 and the leading 0 is dropped, giving "exactly 9 digits after the country code, creating a consistent 12-digit E.164 format" — [sent.dm Saudi phone-number standards](https://sent.dm/en/resources/phone-number-standards/sa); [Calilio Saudi number format](https://www.calilio.com/blogs/saudi-arabia-phone-number-format)
- Mobile prefixes historically map to carriers (050/053/055 STC; 054/056 Mobily; 058/059 Zain; 051/057 Bravo) but number portability means the prefix only shows the original carrier — [Calilio](https://www.calilio.com/blogs/saudi-arabia-phone-number-format)

### Inferences
- Correct Saudi click-to-chat link: `https://wa.me/9665XXXXXXXX?text=<urlencoded>` (12 digits total). A browser page generating links must strip "+", spaces, dashes, and a leading 0 (e.g. `0501234567` -> `966501234567`).
- Because the pre-filled text is the only payload, the realistic per-employee workflow is: link opens the chat, then the operator attaches the PDF manually. No variant of the link (wa.me, api.whatsapp.com/send, whatsapp://send) changes this.
- Since the text is URL-encoded, Arabic text works (percent-encoded UTF-8); the text can carry the employee's name/month so the operator can visually verify they are in the right chat before attaching.

### Gaps
- No official WhatsApp documentation for the `whatsapp://` scheme was found; its behaviour on Windows/macOS is based on community reports only.

## Key Question 2: Do WhatsApp Desktop / WhatsApp Web accept PDFs via drag-and-drop or the share sheet, and does the Web Share API with files open WhatsApp on Android, iOS, Windows, macOS? Which browsers support file sharing in 2025–2026?

### Takeaway
Yes: WhatsApp Web/Desktop accept PDFs (up to 2 GB) via the "+" > Document picker or by dragging the file into the chat; Windows 11's native share sheet can target WhatsApp. The Web Share API with files works in Chromium browsers on Android/Windows/ChromeOS, in Safari on iOS/macOS, but not in desktop Firefox; it always requires a user click per share and the user must pick WhatsApp and (on desktop) the recipient inside WhatsApp.

### Cited Findings
- Official: on desktop/web, documents are sent via Add (+) > Document, or "You can also drag and drop a file into the text field"; "the maximum document size is 2 GB" — [WhatsApp Help Center: How to send media, contacts, or location](https://faq.whatsapp.com/453914586839706/)
- The 2 GB document limit began as a 2022 test (raised from 100 MB; initially Argentina only) — [Infobae, 23 Mar 2022](https://www.infobae.com/en/2022/03/23/whatsapp-increases-the-size-of-documents-that-can-be-sent-to-2-gb)
- Drag-and-drop of any file type into WhatsApp Desktop works; the Document option accepts any file type — [Office Watch, 2024](https://office-watch.com/2024/whatsapp-send-between-your-devices/)
- WARNING (macOS): Macwelt reported on 30 April 2026 that in WhatsApp for Mac versions 26.14.xy and newer, dragging a document (Word, Pages, Excel, PDF, EPUB, PowerPoint, apparently ZIP) into a chat and sending it irreversibly deletes the original from its Finder folder (not to Trash); version 26.12.xy was unaffected; the workaround is to attach with the "+" button, which does not delete files. No fix was confirmed at the time of the article — [Macwelt](https://www.macwelt.de/article/3128392/whatsapp-bug-mac-dokumente.html)
- Windows 11: "Starting with Windows 11 build 22631.3374, the Windows share window now supports sharing with WhatsApp under the 'Share using' section"; if WhatsApp is not installed, the share window offers to install it from the Store — [Windows Insider blog](https://blogs.windows.com/windowsdeveloper/?p=56290); [Neowin](https://www.neowin.net/news/windows-11-share-app-now-supports-whatsapp-in-build-226352850-kb5033453/); Windows Latest reported the Beta build KB5032283 let users share "pictures, videos, and documents to WhatsApp from the share menu", e.g. from File Explorer — [Windows Latest, 10 Dec 2023](https://windowslatest.com/2023/12/10/windows-11-kb5032283-beta-channel-integrates-whatsapp-into-share-menu)
- Web Share API requirements: "available only in secure contexts (HTTPS)"; "requires that the current document have the web-share Permissions Policy and transient activation. (It must be triggered off a UI event like a button click and cannot be launched at arbitrary points by a script.)"; `.pdf` (application/pdf) is listed as a usually-shareable file type; MDN flags the feature as "not Baseline because it does not work in some of the most widely-used browsers" — [MDN: Navigator.share()](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)
- web.dev: feature-detect with `navigator.canShare({files})` (it only supports the `files` property); it "can only be used on a site that is accessed via HTTPS" and "must be invoked in response to a user action such as a click"; "Certain types of audio, image, pdf, video, and text files can be shared" — [web.dev: Web Share](https://web.dev/articles/web-share)
- Browser support per caniuse (global usage 94.17%): Chrome desktop partial 89–127, full from 128; Edge full from 95; Safari macOS from 12.1; Firefox desktop not supported in any version (through 161); Opera from 114; Chrome for Android supported; Safari iOS from 12.2; Samsung Internet from 8.2; Firefox for Android supported; stock Android Browser, Opera Mini, UC Browser, KaiOS not supported — [caniuse: Web Share API](https://caniuse.com/web-share)
- A scrape of MDN's compatibility data shows a footnote "Only supported on ChromeOS and Windows" attached to the Chrome 75–114 range for share(), and a `files` parameter row suggesting Chrome Android 76 / Safari iOS 14 / Safari macOS 14 — but the scraped table columns were garbled, so treat the exact numbers as unconfirmed — [MDN (ko) Navigator.share](https://developer.mozilla.org/ko/docs/Web/API/Navigator/share)
- iOS/Safari quirk: WebKit bug 251500 reports that when `navigator.share()` receives both `text` and `files`, iOS ignores the files, whereas Android shares the file with the text as caption — [WebKit Bugzilla 251500](https://onbugs.webkit.org/show_bug.cgi?id=251500)
- Android quirk: an Opera-for-Android user reported `navigator.share` with a jsPDF-generated PDF failing while the same code worked on iOS — [Opera forums](https://forums.opera.com/user/ariverof)
- File shares to WhatsApp on Android depend on the correct MIME type and a real file (not base64); WhatsApp rejected a PDF sent with MIME `image/*` — [B4X forum](https://b4x.com/android/forum/threads/share-pdf-file-to-whatsapp.80770/?amp=1); [react-native-share notes](https://github.com/pang0018/react-native-share)
- Broadcast lists (see Q3) are explicitly "not supported on Windows, Mac, or Web" — [WhatsApp Help Center: How to use broadcast lists](https://faq.whatsapp.com/861663048350950/)

### Inferences
- An offline browser page cannot use the Web Share API unless it is served over HTTPS or treated as a secure context; a page opened via `file://` is generally not a secure context, so `navigator.share` with files will typically be unavailable from a double-clicked local HTML file. (Inference from MDN's HTTPS requirement; localhost would count as secure but that requires running a local server, which the brief excludes.) This is a decisive practical blocker for a "generate PDF in browser, then share()" design on desktop.
- Even where share() works, each call needs its own user click, and the OS share sheet does not pre-select the recipient: on Android the user taps WhatsApp then picks a contact; on Windows 11 the share sheet hands the file to the WhatsApp app, which then asks for a recipient. So share() saves the "+ > Document > file dialog" steps but adds a "pick recipient" step; it cannot be combined with the wa.me link's recipient pre-selection in a single action.
- WhatsApp Desktop (Windows) with files dragged from File Explorer is the fastest no-API route on desktop; on macOS, attach via "+" only, given the April 2026 data-loss bug.

### Gaps
- No authoritative per-platform (Windows/macOS/Linux) table for Chrome desktop file-sharing support was retrievable; Linux Chrome appears unsupported from the MDN footnote but this is unconfirmed.
- Whether WhatsApp's Windows share-target integration is still present in current stable Windows 11 builds (2026) was not verified beyond the 2023–2024 Insider/stable reports.
- No source confirms whether WhatsApp Desktop's Windows share target accepts a PDF plus pre-filled recipient; it almost certainly does not (inference).

## Key Question 3: Current WhatsApp limits — broadcast list size, same message to many contacts, rate/spam detection, Business-app features — and what triggers bans

### Takeaway
Broadcast lists hold max 256 contacts, deliver only to people who have saved the sender's number, cannot be used from Desktop/Web, and some countries now have a monthly broadcast cap. Broadcasts cannot send a different file to each recipient, so they are useless for individual payslips. Spam detection is behavioural (many new chats to unsaved numbers, blocks/reports, automation tools), producing first a temporary "restricted" state (no new chats, no linked devices) and then permanent bans; Business-app bans without a "Request review" option are final.

### Cited Findings
- "You can include up to 256 contacts in each broadcast list"; you can create as many lists as you like; only contacts who "have added your number to their contacts" receive the broadcast; replies arrive as 1:1 chats; "broadcast lists aren't supported on Windows, Mac, or Web" — [WhatsApp Help Center: How to use broadcast lists](https://faq.whatsapp.com/861663048350950/)
- A localized version of the same page adds that people in some countries "might see a monthly broadcast limit. This feature is rolling out gradually and might not be available everywhere" — [WhatsApp Help Center (da_DK locale)](https://faq.whatsapp.com/861663048350950/?locale=da_DK&cms_platform=android)
- Third-party guides agree the 256 cap applies to both the standard and the WhatsApp Business app and warn that sending the same message to many lists in quick succession can trigger spam filters — [Qiscus](https://www.qiscus.com/en/blog/whatsapp-broadcast-limit/); [Qualimero](https://qualimero.com/en/blog/whatsapp-broadcast-create)
- Restricted accounts (official, via search snippet): "any user engaging in spam, automated, or bulk messaging could have their account banned"; a temporary restriction lifts automatically; while restricted "You can continue to communicate with contacts and groups you've exchanged chats or calls with previously. However, you can't start chats or calls with new contacts", create groups, or use linked devices — [WhatsApp Help Center: About restricted accounts](https://faq.whatsapp.com/717472490411581/)
- Temporarily banned accounts: the message can mean an unofficial client or data scraping; "if you don't switch to the official app or stop, your account might be permanently banned" — [WhatsApp Help Center: About temporarily banned accounts](https://faq.whatsapp.com/1848531392146538)
- Business-app bans: "If you think your WhatsApp Business account was banned by mistake, tap Request review in the app"; if no review option appears, the ban is final; "third party services can't ban your WhatsApp Business account or remove your account ban" — [WhatsApp Help Center: About account bans on the WhatsApp Business app](https://faq.whatsapp.com/723378546580115)
- WhatsApp Business Policy (page last updated 23 Sept 2026): businesses may contact people only if the person gave their number/username and "you have received opt-in permission from the recipient"; "messaging people at scale in an unauthorized manner" is a violation; WhatsApp may "limit or remove your access to or use of WhatsApp for Business" and, for violations, "prohibit you and your organization from all future use of WhatsApp products and services"; businesses may not forward or share one customer's chat information with another — [WhatsApp Business Policy](https://whatsappbusiness.com/policy/)
- Third-party descriptions of the restriction mechanics: triggered by "sending a large number of messages to users you don't know"; also by mass group creation/adding; Green-API (2025) says the restriction "only lasts for 24 hours" and that WhatsApp now warns before banning; Whapi shows a WhatsApp Web banner with a countdown of up to several days while existing chats keep working — [Green-API blog 2025](https://green-api.com/en/blog/2025/whatsapp-has-become-more-loyal-now-a-warning-instead-of-a-ban/); [Whapi help desk](https://support.whapi.cloud/help-desk/blocking/account-on-linked-devices-is-restricted-and-the-message-status-is-failed); [Privyr](https://www.privyr.com/blog/whatsapp-bans-automated-bulk-send/)
- Ban signals per a developer guide: machine-learning based, no fixed message cap; recipient mix (strangers vs saved contacts) and block/report rate matter more than raw volume — [checkleaked developer guide](https://whatsapp.checkleaked.cc/blog/avoid-whatsapp-ban)
- Unofficial automation libraries carry acknowledged ban risk: a whatsapp-web.js-style README warns the library is unofficial and "cannot guarantee you won't be blocked" — [whatsapp-web-automation README on jsDelivr](https://cdn.jsdelivr.net/npm/whatsapp-web-automation@1.0.0/README.md); [bot.space 2025 risk analysis](https://www.bot.space/blog/whatsapp-api-vs-unofficial-tools-a-complete-risk-reward-analysis-for-2025)
- Business app feature limits: "the maximum number of stored quick replies allowed is 50" and media cannot be included in quick replies on Web/Desktop — [WhatsApp Help Center: How to use quick replies](https://faq.whatsapp.com/1791149784551042/); "you can create up to 20 labels" (labels are being converted to "lists", gradual rollout) — [WhatsApp Help Center: How to use labels](https://faq.whatsapp.com/3398508707096369/)
- For contrast only (paid): Meta moved to per-message billing on 1 July 2025 and cut Saudi utility/authentication rates on 1 Oct 2025; a Saudi marketing-rate increase and SAR billing took effect 1 Apr 2026 — [Meta: Pricing on the WhatsApp Business Platform](https://developers.facebook.com/docs/whatsapp/pricing); a BSP rate card lists Saudi utility messages at roughly USD 0.012 each — [SleekFlow pricing](https://help.sleekflow.io/en_US/whatsapp/pricing)

### Inferences
- 1,000 employees = at least four broadcast lists, but broadcasts deliver one identical payload to all, so they can at most carry a generic "your payslip is ready" notice, never the individual PDFs. They also fail silently for any worker who has not saved HR's number, and must be sent from the phone (not Desktop).
- Opening ~1,000 wa.me links to numbers that are not saved contacts and have never messaged the sender is exactly the "many new chats to unknown numbers" pattern that triggers the temporary restriction; the restriction also disables linked devices, which would cut off WhatsApp Desktop mid-run. Risk is markedly lower if (a) all employees are imported as saved contacts on the HR phone, (b) employees have previously messaged HR (an existing chat), and (c) sending is spread over time.
- Chrome-extension "bulk senders" and whatsapp-web.js-type bots fall under "unauthorized" tools; a Business-app ban is final if no review option appears, so the HR number itself is at stake.
- At ~USD 0.012 per utility message, the paid API route would cost on the order of USD 12–15 per month for 1,000 payslips plus BSP fees — a useful comparison when weighing hours of manual clicking against account-ban risk (contrast only; outside the brief's "solution" set).

### Gaps
- No official numeric thresholds (messages/hour, new chats/day) exist publicly; all figures are vendor inferences.
- The monthly broadcast cap's size and which countries (whether Saudi Arabia) are covered were not found.
- The official "About forwarding limits" page could not be fetched; forwarding a single PDF to many chats is capped (five chats per forward per widely reported WhatsApp policy) but I could not retrieve the exact current wording, so this is listed as a gap rather than a cited fact.

## Key Question 4: Is there a legitimate, free, offline-friendly way to semi-automate sending one unique file to each of 1,000 contacts? Time per employee?

### Takeaway
There is no fully automated free route. The only legitimate semi-automation is a generated page of per-employee wa.me/whatsapp:// links (optionally as QR codes) opened in WhatsApp Desktop, with the operator attaching each PDF by drag-and-drop or the Document picker; third-party "bulk sender" extensions attach one file per campaign, not one per contact, and risk bans. Realistic effort is roughly 20–40 seconds and 6–9 clicks per employee, i.e. roughly 6–11 operator-hours for 1,000 workers, before accounting for restriction pauses.

### Cited Findings
- Click-to-chat links need no authentication, developer account or code, and a person still has to press send — [Linkly guide](https://linklyhq.com/blog/whatsapp-link-generator)
- On desktop, api.whatsapp.com / wa.me links open the installed app or WhatsApp Web — [WordPress.org support](https://wordpress.org/support/?p=10680850); `whatsapp://send?phone=...&text=...` opens the Windows app directly (community report) — [Edureka](https://www.edureka.co/community/173303/open-whatsapp-windows-directly-from-python-program-using-url)
- Attaching in Desktop/Web: Add (+) > Document > pick file, or drag the file into the text field — [WhatsApp Help Center](https://faq.whatsapp.com/453914586839706/)
- Chrome Web Store bulk senders describe "type a message and optionally attach a file" per campaign; others personalize only text placeholders from CSV columns; none found documents a per-row attachment column — [WhatsApp Bulk Sender (Chrome Web Store)](https://chromewebstore.google.com/detail/dmkahpklacmbdkdgckoninbimcemailp); [Extension Auditor listing](https://extensionauditor.com/scan/whatsapp-bulk-message-sender-ckcfcgpbckidfomaicbnnjgmhjhbkinl); [SendPro12 support](https://chrome.google.com/webstore/detail/sendpro12/ngecmgoblhegkdghknpfbkeehhefpdhc/support); [HappyInAI on Gumroad](https://ashikdotme.gumroad.com/l/whatsapp-bulk-message-sender)
- Such extensions and bots are the "unofficial tools" category that WhatsApp's restriction/ban pages and vendor guides warn about — [WhatsApp Help Center: temporarily banned](https://faq.whatsapp.com/1848531392146538); [Privyr](https://www.privyr.com/blog/whatsapp-bans-automated-bulk-send/)
- Payroll vendors that "automate" WhatsApp payslips all do so through the paid API or by sending a link rather than the file: Zoho Payroll (WhatsApp for Business integration, early access, template notifications; a Saudi-specific Zoho Payroll app launched Feb 2025) — [Zoho Payroll updates Feb 2025](https://help.zoho.com/portal/en/community/topic/zoho-payroll-product-updates-february-2025); [Zoho Payroll WhatsApp feature](https://www.zoho.com/in/payroll/features/payroll-whatsapp/); Odoo payslip-WhatsApp modules — [Odoo app store](https://apps.odoo.com/apps/modules/16.0/bi_payslip_whatsapp_integration); an n8n workflow that stores PDFs in Google Drive and WhatsApps a link — [InfyOm n8n workflow](https://infyom.com/workflows/n8n-automated-payroll-slip-sender-on-whatsapp)
- Quick replies cannot carry media on Web/Desktop (so they cannot be used as a "canned attachment" shortcut on the PC) — [WhatsApp Help Center: quick replies](https://faq.whatsapp.com/1791149784551042/)

### Inferences
- Recommended free workflow (Windows PC, WhatsApp Desktop installed, phone linked):
  1. The offline page generates, per employee, a PDF named by a stable key (e.g. `0421_Ahmed_2026-09.pdf`) into one folder, plus an HTML index with one `https://wa.me/9665XXXXXXXX?text=...` (or `whatsapp://send?phone=...&text=...`) row per employee, sorted the same way as the files, with a checkbox/strike-through so the operator can track progress.
  2. Operator clicks the link (1 click, plus possibly a one-time "Open WhatsApp?" browser prompt), WhatsApp Desktop opens the chat with the pre-filled greeting; operator presses Enter to send the text (1), drags the matching PDF from an adjacent File Explorer window into the chat (1 drag), confirms Send (1), returns to the index and ticks the row (1–2). About 5–7 interactions and roughly 20–30 s when files and rows are in the same order; using "+ > Document > file dialog" instead of drag adds 2–3 clicks plus typing/scrolling, roughly 30–45 s.
  3. 1,000 employees therefore cost roughly 6–11 hours of continuous operator time per pay cycle (my estimate; no published benchmark exists). Splitting across 2–3 HR staff/phones also spreads the "new chat" signal.
- QR-per-employee is simply the same wa.me link rendered as a QR code; it is useful for the opposite direction (worker scans a QR to open a chat with HR and thereby creates the opt-in/existing chat), not for pushing files.
- Android-phone-only variant: open each employee's PDF in a file manager, Share > WhatsApp > pick contact > Send; comparable click count but slower because of touch navigation and contact search; and the Web Share API from the offline page will not fire from a `file://` page (secure-context requirement), so the page cannot shortcut it.
- Risk-mitigation steps that follow from the official wording: import the 1,000 workers as contacts on the HR phone first; have workers message HR once (e.g. via a QR poster) so every subsequent send is a reply in an existing chat; keep the HR number on the official WhatsApp Business app (never a modified client); avoid extensions/bots; pace sends (e.g. 100–200 per hour) and stop immediately if the "restricted" banner appears, since it also disables linked devices.

### Gaps
- No published measurement of clicks or seconds per WhatsApp document send exists; the time estimates above are inferences.
- No official statement on whether opening many wa.me links in a short time is itself a ban signal (as distinct from sending to unsaved numbers).
- No source confirms whether `whatsapp://send` deep links can be opened directly from a `file://` page without a browser prompt on each click; browser behaviour (Chrome's "Always allow" option) is likely but unverified.

## Key Question 5: Privacy/security concerns of payslips over WhatsApp, and how Gulf HR practitioners actually do it

### Takeaway
Messages are end-to-end encrypted in transit, but copies land on the worker's device, in cloud backups that are not end-to-end encrypted by default, on any linked devices, and in screenshots/forwards; HR commentary flags confidentiality and fraud risks and recommends password-protected PDFs or links instead of attachments. No Gulf-specific survey of practice was found; evidence of actual practice comes from payroll vendors selling WhatsApp payslip features into the region and generic HR advice.

### Cited Findings
- WhatsApp introduced optional end-to-end encrypted backups in October 2021, secured by a user password or 64-digit key; "neither WhatsApp nor your backup service provider will be able to read your backups" once enabled — [WhatsApp blog](https://blog.whatsapp.com/end-to-end-encrypted-backups-on-whatsapp); [Meta newsroom](https://about.fb.com/news/2021/10/end-to-end-encrypted-backups-on-whatsapp/)
- As of an August 2025 guide, "By default, backups you save to Google Drive or Apple's iCloud are not protected by WhatsApp's end-to-end encryption"; E2EE backups must be switched on under Settings > Chats > Chat backup — [ExpressVPN guide](https://expressvpn.com/blog/enable-end-to-end-encryption-in-whatsapp)
- HR Katha (India, on the draft Labour Code proposal to allow salary slips via SMS/email/WhatsApp) argues WhatsApp "could compromise employees' financial privacy", "will naturally violate the confidentiality agreement between the employers and employees", and that rising cyber fraud makes it a questionable channel — [HR Katha](https://www.hrkatha.com/news/labour-code-2020-should-whatsapp-be-used-to-issue-salary-slips-statements/)
- A payroll vendor recommends password-protecting payslips because they contain "salary details, tax deductions, bank information, and payroll records" — [Pocket HRMS](https://www.pockethrms.com/blog/password-protected-payslips-pocket-hrms-software/); Pocket HRMS added a feature to send payslips directly to an employee's WhatsApp number — [Pocket HRMS product updates Dec 2022](https://docs.pockethrms.com/product-updates/updates-2022/december-2022)
- Zoho Payroll positions WhatsApp as a channel for payroll notifications with "secure links or attachments" and launched a Saudi-specific payroll app for GCC businesses in 2025 — [Zoho Payroll WhatsApp feature](https://www.zoho.com/in/payroll/features/payroll-whatsapp/); [Zoho Payroll updates Feb 2025](https://help.zoho.com/portal/en/community/topic/zoho-payroll-product-updates-february-2025)
- WhatsApp Business Policy prohibits sharing one customer's chat information with another and bars requesting full financial account numbers in chat — [WhatsApp Business Policy](https://whatsappbusiness.com/policy/)
- Saudi PDPL (in force 14 Sept 2023, grace period ended Sept 2024): names, salaries, national IDs etc. are personal data; employers need a legal basis (consent, contract, legitimate interest), must provide a privacy notice before collection, and employees can withdraw consent and request access/correction — [Al Tamimi & Co.](https://www.tamimi.com/news/saudi-arabias-new-personal-data-protection-law-key-considerations-for-employers/); [Employment Law Worldview](https://www.employmentlawworldview.com/new-gcc-rules-for-employers-part-3-revised-ksa-personal-data-protection-law-ksa/)
- In the UAE, "WhatsApp or email conversations about your salary" are listed among documents workers can use when reporting unpaid wages — [Gulf News](https://gulfnews.com/preview/story/wgJUADVcp--U5BlvF2ZoWiduyxzRM_aFngrvsRMo93qs6jeYcuDlzmcg9HeJLWke) (shows WhatsApp is an accepted de facto employer-worker channel in the Gulf)
- Saudi wage payment itself runs through WPS/Mudad: every private employer must pay via Mudad-approved channels and file a monthly Salary Information File — [Mynd Solutions](https://www.myndsolution.com/best-practices/mudad-wps-salary-compliance-saudi-arabia/); [Mercans WPS glossary](https://mercans.com/glossary/wage-protection-system-wps/)

### Inferences
- Practical mitigations consistent with the sources: password-protect each PDF (e.g. with the worker's Iqama/ID number or date of birth, communicated out-of-band), keep the PDF free of full bank account numbers, send from a dedicated HR Business account rather than a personal phone, enable E2EE backup on the HR phone, and record consent/opt-in to WhatsApp delivery in the employment paperwork (PDPL legal basis). Note the misdirection risk: a wrong digit in a 12-digit number sends a stranger another worker's payslip, which both PDPL and WhatsApp's own policy would treat as a breach; the pre-filled greeting with the worker's name helps the operator catch this before attaching.
- The vendor landscape suggests that in India and the Gulf the "WhatsApp payslip" is already a mainstream expectation, but that implemented versions are either API-based or link-based (portal/Drive link), not attachment-by-hand.

### Gaps
- No published survey, forum thread, or regulator guidance on how Saudi/GCC HR teams actually distribute payslips today; practitioner accounts (Reddit, HR forums) did not surface in searches.
- No SDAIA/PDPL guidance specific to messaging apps as a channel for salary data was found.
- Whether Saudi Labor Law or MHRSD requires a payslip document at all (beyond WPS records) was not confirmed from primary sources.

## Key Question 6: Anything specific about WhatsApp usage, Business API resellers, or regulation in Saudi Arabia (CST/CITC)?

### Takeaway
WhatsApp is the most-used app in Saudi Arabia (CST reports 92.7% usage among internet users, with 99%+ internet penetration), so reach is not the problem. VoIP restrictions were lifted in 2017; CST's 2022 anti-spam regulation and spam-reporting hotline target unsolicited messaging, and the PDPL governs the salary data itself. ### Inferences
- For a Saudi blue-collar workforce, WhatsApp delivery reaches essentially everyone with a smartphone, including workers using low-end Android devices; the chief local constraints are PDPL (lawful basis, security of salary data) and WhatsApp's own anti-spam machinery, not CST telecom rules, which target SMS/voice spam and licensed operators rather than an employer's 1:1 WhatsApp messages to its own staff.
- Many migrant workers keep home-country SIMs/WhatsApp numbers; the link generator must therefore not assume +966 and should accept any E.164 number (inference from the prevalence of expatriate labour; no source quantified this).
